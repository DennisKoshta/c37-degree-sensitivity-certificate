# C37: no Boolean function of degree 4 has sensitivity 10 (exact certificate)

**Claim.** Every Boolean function f of real degree at most 4 has sensitivity s(f) ≤ 9. Equivalently, there is no
g : {0,1}^10 → {0,1} with deg g ≤ 4, g(0) = 0 and g(e_i) = 1 for i = 1..10. The bound is attained by NAE₃∘NAE₃
(9 variables, degree 4, sensitivity 9). Together with the (4,2) and (7,3) certificates, the largest sensitivity at
degree d ≤ 2, 3, 4 is 3, 6 and 9.

This relates to constant 37a of [teorth/optimizationproblems](https://teorth.github.io/optimizationproblems/constants/37a.html),
the degree–sensitivity exponent C₃₇ = sup log s(f) / log deg f. **It is not a new bound.** C₃₇ ≥ log₃ 6 stands. A
fully sensitive (10,4) function would have given C₃₇ ≥ log₄ 10 ≈ 1.661 by composition, and the certificate shows that
none exists. Proskurin (arXiv:2101.08600, §5) singled out this case and left it open. Maitra–Mukherjee–Stănică–Tang
(Discrete Appl. Math. 2025) excluded only rotation-symmetric functions. Larger degrees are not touched. The
mathematics, the literature and what is not claimed are in [`WRITEUP.md`](WRITEUP.md).

The proof is a branch-and-bound tree over the 1024 truth-table values: 957 nodes, 479 leaves, depth 15. Each leaf
carries integer multipliers of the 638 degree constraints (the Möbius coefficients a_S = 0 for |S| ≥ 5), which prove
the leaf's box infeasible. It is checked two ways:

- `checker/check_cert.py` uses only the Python standard library and exact integers. It rebuilds the constraints
  from (n, d).
- The certificate is translated to VIPR 1.0 and checked with the third-party exact MILP certificate checker
  [`viprchk`](https://github.com/ambros-gleixner/VIPR).

## Reproduce

Checking needs `python3` (3.8 or later, standard library only) and `xz`. Building `viprchk` also needs `curl`, `git`,
`make`, and C and C++ compilers. Run from the repository root:

```sh
sha256sum -c SHA256SUMS
# 1. exact checker: "VALID: no f on 10 variables with deg <= 4 fully sensitive at 0 (479 leaves, depth 15, ...)" (~15 s)
xz -dc certificates/d10_4.cert.xz > d10_4.cert
python3 -I checker/check_cert.py d10_4.cert
python3 -I checker/check_cert.py certificates/d7_3.cert
python3 -I checker/check_cert.py certificates/d4_2.cert
# 2. viprchk: build it (a few minutes, mostly GMP), translate, check: "Infeasibility verified."
VIPRCHK=$(sh tools/build_viprchk.sh build | tail -n 1)
python3 -I checker/to_vipr.py d10_4.cert d10_4.vipr
sha256sum d10_4.vipr   # f2e8a0650842e7e445a0fad2988b934aecf8731ee5ed3b200847f6e419173a8e
"$VIPRCHK" d10_4.vipr > d10_4.viprchk.log; tail -n 3 d10_4.viprchk.log
for c in d7_3 d4_2; do python3 -I checker/to_vipr.py certificates/$c.cert $c.vipr; "$VIPRCHK" $c.vipr | tail -n 3; done
# 3. sharpness: NAE3 o NAE3 has degree 4 and sensitivity 9 -> "VALID n_vars=9 deg=4 s=9 ..."
python3 -I sharpness/nae_nae.py | cmp - sharpness/nae_nae_9_4.txt
python3 -I verifier/degree_sensitivity.py sharpness/nae_nae_9_4.txt
```

`viprchk` checks the VIPR file against the problem written in that file: 1024 integer variables, 2048 bounds and 638
equality rows. That problem section is generated by `checker/to_vipr.py` from (n, d) alone. A reader should satisfy
themselves that it is the system above; it is short and regular.

**Negative controls.** Run these in the same shell, after the block above. A certificate with one leaf multiplier
negated must fail the exact checker; `to_vipr.py` refuses it too. A VIPR file with one multiplier of the first leaf
derivation negated must fail `viprchk`:

```sh
awk 'BEGIN{d=0} /^l /&&!d{$4=-$4; d=1} {print}' d10_4.cert > bad.cert
python3 -I checker/check_cert.py bad.cert; echo "exit $?"          # "leaf certificate fails", exit 1
awk 'BEGIN{d=0} /^F/&&/ lin /&&!d{$9=-$9; d=1} {print}' d10_4.vipr > bad.vipr
"$VIPRCHK" bad.vipr > bad.viprchk.log; echo "exit $?"; grep -m1 Failed bad.viprchk.log   # exit 255, "Failed to derive constraint F2695"
```

**Regenerate (optional).** About 7–9 min on one core, with numpy, scipy and highspy (`generator/requirements.txt`).
The output should be byte-identical to the committed certificate:

```sh
python3 -m venv venv && venv/bin/pip install -r generator/requirements.txt
OMP_NUM_THREADS=1 venv/bin/python -I generator/certify.py 10 4 regen.cert && sha256sum regen.cert   # 7dc38b37...
```
